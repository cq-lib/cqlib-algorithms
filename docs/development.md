# 开发规范

本文只规定跨算法通用的开发规则。具体类的参数、返回值、异常和数学语义写在源码
docstring；算法的使用方法和结果解释写在 `docs/user-guide/`。

## 目录与依赖

- 公共协议放在 `protocols/`，具体实现放在 `operators/`，完整工作流放在
  `algorithms/`，纯线路变换放在 `transforms/`。
- 化学、晶格和振动等领域数据模型及其中间表示放在 `extension/`。通用算子可以依赖
  领域扩展，领域扩展不得反向依赖具体算子或完整算法；领域扩展内部保持低层表示到
  高层系统模型的单向依赖。`extension/many_body/` 持有跨领域的低层表示；例如
  `ModalSpace`、`VibrationalOp` 和 one-hot 映射由振动领域模型单向复用。
- 只为已经实现的能力建立模块，不预建空分类。
- 算法依赖公共协议，不直接绑定具体模拟器、云平台或适配器。
- 复用 Cqlib Core 的线路、门、参数、Hamiltonian 和执行能力，不在本库重复实现
  等价底层对象。
- 模块依赖保持单向：协议不得依赖具体组件，组件不得依赖完整算法。

## 公共接口

- 公共类显式继承对应协议；批处理输入和输出保持顺序与长度一致。
- 构造函数保存稳定配置，`build_circuit()` 和 `run()` 不修改调用方对象。
- 请求对象含有可变 Cqlib 对象时，执行前重新验证关键约束。
- 量子比特、参数、位串、端序和全局相位约定必须明确；遵循 Cqlib 小端约定时也要
  在受影响的公共 API 中说明。
- 拒绝无意义参数、非有限数值、维度不匹配和不受支持的线路结构，并使用明确异常。
- 不以 `prefix` 替代组件实例隔离、参数共享或训练语义；共享参数必须由接口显式表达。

## 辅助函数归属

- 仅被一个模块使用的辅助函数留在该模块内，并以下划线命名。
- 同一子包多个模块复用的辅助函数放在该子包的 `_utils.py`、`_validation.py` 等私有模块。
- 多个一级子包复用的辅助函数放在 `src/cqlib_algorithms/` 下的私有公共模块。
- 抽取前先确认语义和错误行为一致；不要只因代码形状相似而合并。

## 科学正确性

- 先写清数学对象、寄存器布局、线路时间顺序、参数含义和适用假设，再实现代码。
- 对关键公式使用独立参考计算验证，不能用被测实现生成期望值。
- 区分精确、近似和有限-shot 结果；容差只表示数值比较误差，不表示统计置信度。
- 随机算法必须支持可复现的随机源；资源上可能指数增长的路径应在分配前检查规模。
- 文献引用必须与实现原理直接对应；找不到可靠来源时不添加推测性引用。

## 测试

每个公共能力至少覆盖：

1. 正常输入和最小有效规模；
2. 边界值、无效类型、无效数值和维度不匹配；
3. 批处理顺序、空批次及输入不被修改；
4. 参数命名、量子比特顺序、端序和重复构建稳定性；
5. 与独立解析结果、矩阵或概率分布的科学正确性对照；
6. 组件替换以及与相邻协议的集成路径。

修复缺陷时先增加能够复现问题的测试。测试若需要共享工具，按与源码相同的最小
作用域原则放置。

## Docstring 与用户文档

- 具体格式、文件头、引用位置、私有辅助函数命名和行注释规则见
  [文档与 Docstring 规范](documentation-style.md)。
- 公共 API 的参数、返回值、异常、适用条件和必要数学语义以源码 docstring 为准。
- 模块说明和简单属性使用一句话；普通公共组件通常保持在 10–25 行，复杂算法只在
  数学语义或资源边界确有需要时扩展。
- 使用英文结构化段落（`Args`、`Returns`、`Raises`）；已有类型标注不重复
  冗长类型描述。
- 私有辅助函数只说明非显然语义，不复制实现步骤。
- 用户指南面向“如何选择、调用和解释结果”，不复制完整接口字段、内部调用链、
  测试清单、迁移历史或阶段性审计记录。
- 当前能力、未来方案和历史分析必须分开；未实现能力不得写入当前能力清单。

## 提交前检查

```bash
uv run --no-sync pytest
uv run --no-sync mypy src/cqlib_algorithms
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv run --no-sync python -m build
```

如果检查受环境或既有基线问题阻塞，应记录实际命令、失败原因和未验证范围，不得将
未运行的检查报告为通过。
