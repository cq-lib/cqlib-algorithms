# BB84 协议实验

`BB84` 实现 BB84 的制备—测量、基筛选和抽样误码率检查流程。该组件用于算法教学、
仿真和后端接口验证；输出只是候选原始密钥材料，不是可直接用于密码系统的安全密钥。

## 协议范围

调用方显式提供：

- Alice 的比特序列；
- Alice 与 Bob 对每个信号选择的 <img src="../../assets/formulas/inline/inline-bbeebd879e1dff69.svg" alt="Z" style="vertical-align: -0.000pt;"> 或 <img src="../../assets/formulas/inline/inline-4b68ab3847feda7d.svg" alt="X" style="vertical-align: -0.000pt;"> 基；
- 从基匹配位置中公开用于参数估计的原始信号索引；
- 可接受的抽样 QBER 上限；
- 可选的 Eve 逐信号截获—重发计划。

组件不生成随机数。真实协议要求经过认证的经典信道以及密码学安全随机源，因此所有
随机选择都由调用方负责。

本实现没有提供身份认证、信息协调、纠错、隐私放大、有限密钥长度估计、可组合安全
证明、设备建模或一般窃听攻击模型。`parameter_estimation_passed` 只表示当前公开样本的
经验 QBER 是否不高于阈值，不表示已经获得安全密钥。

`BB84Basis.X` 使用 Hadamard 基：

每个信号复用 `BasisStateInitialization(1, bit)`。Alice 选择 X 基时追加 H；Bob
选择 X 基时在终端测量前追加 H。终端测量由注入的公共 `Sampler` 完成，每个信号
固定使用一个 shot。

Alice 和 Bob 选择相同基时，理想无噪声测量确定性恢复 Alice 的比特；选择不同基时，
两个结果各以 <img src="../../assets/formulas/inline/inline-d939926f05444b0f.svg" alt="1/2" style="vertical-align: -4.000pt;"> 概率出现。算法只在相同基的位置保留数据。

## 请求和结果

```python
from cqlib_algorithms import BB84, BB84Basis
from cqlib_algorithms.operators import StatevectorSampler

Z, X = BB84Basis.Z, BB84Basis.X
result = BB84(StatevectorSampler()).run(
    alice_bits=(0, 1, 0, 1),
    alice_bases=(Z, X, Z, X),
    bob_bases=(Z, X, X, X),
    parameter_estimation_indices=(0, 1),
    max_qber=0.10,
)
print(result.sifted_indices)  # (0, 1, 3)
print(result.qber, result.parameter_estimation_passed)  # 0.0 True
print(result.candidate_indices)  # (3,)
```

单任务入口 `run(alice_bits, alice_bases, bob_bases, *, max_qber, parameter_estimation_indices=(), intercept_resend_bases=None)` 返回一个结果。位与基均使用元组。
`max_qber` 是必填关键字参数，必须由调用方根据其具体协议、设备模型和
安全分析显式选择；本组件不提供所谓通用安全默认值。

`parameter_estimation_indices` 使用发送序列中的原始位置，而不是筛选后数组的位置。它
必须升序、唯一、范围合法，并且只能指向 Alice 与 Bob 基匹配的位置。公开样本会从
候选材料中移除。

`BB84Result` 保留：

- `sifted_indices`：基匹配的原始位置；
- `parameter_estimation_indices`：公开比较的位置；
- `alice_sifted_bits`、`bob_sifted_bits`：双方的筛选后数据；
- `qber`：公开样本中的不同比特数除以样本数；
- `parameter_estimation_passed`：`qber <= max_qber`；
- `candidate_indices` 与双方的 `candidate_bits`：去除公开样本后的候选材料；
- `candidate_keys_match`：候选比特当前是否相同。

允许没有基匹配位置，也允许参数估计样本为空。样本为空时 `qber` 和
`parameter_estimation_passed` 均为 `None`，因为没有证据可以形成通过或失败结论。
允许公开全部筛选位，此时候选元组为空。空候选元组相等只是数据相等关系，不代表
成功生成了密钥。

## 截获—重发实验

设置 `intercept_resend_bases` 后，组件执行教材式的独立截获—重发。
元素为 `BB84Basis.Z` 或 `BB84Basis.X` 时 Eve 截获该信号；元素为
`None` 时该信号直接从 Alice 进入 Bob 路径。元组必须与发送序列等长。
对每个被截获的信号：

1. Alice 按给定比特和基制备全部信号；
2. Eve 按给定基逐信号测量；
3. 组件读取 Eve 的实际测量结果；
4. Eve 以自己的测量基和实际结果重新制备信号；
5. Bob 按自己的基测量重发信号。

全部被截获的 Eve 信号在第一次批量 Sampler 调用中执行；获取真实 Eve
结果后，全部 Bob 信号
在第二次批量调用中执行。没有 Eve 时，整个请求批次只需一次压平的 Sampler 调用。
等长但全部为 `None` 的计划也不产生 Eve 执行，因此与无截获相同，只调用一次
Bob 批处理。
所有请求都会在第一次外部执行前完成校验和初始线路构建。

若 Alice、Bob 和 Eve 独立均匀选择基，只考察 Alice 与 Bob 基匹配的位置，Eve 有
一半概率选错基；选错后 Bob 又有一半概率得到错误比特，因此理想截获—重发的期望
QBER 是 <img src="../../assets/formulas/inline/inline-f051aea4c97e881a.svg" alt="\tfrac12\times\tfrac12=25\%" style="vertical-align: -6.000pt;">。本组件只模拟这一特定攻击，不把它扩展解释为一般攻击
或安全界。

## 批处理和执行契约

`BB84.run` 接受请求序列并按输入顺序返回结果。每个信号对应一个
`SamplerRequest(circuit, qubits, shots=1)`。结果通过公共
`require_sampler_results` 检查，必须满足：

- 返回列表与请求数量一致；
- 每项是成功终态 `ExecutionResult`；
- shots、宽度及量子比特顺序与请求一致；
- 完整频数总和等于一个 shot。

## 理论与工程边界

协议依据 Bennett 与 Brassard 1984 年提出的四态量子密码方案。现代有限密钥安全
分析还需要统计波动、纠错泄漏、平滑熵和隐私放大等处理，例如 Tomamichel 等人的
有限密钥分析；这些不应由本实验结果字段暗示完成。工程化 QKD 系统还需要密钥管理、
应用接口和设备安全边界，ETSI 的 QKD 接口规范展示了这些协议实验之外的系统层职责。
